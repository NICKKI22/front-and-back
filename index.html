01 / mapa da aplicação

Do clique à resposta.

Leia de cima para baixo. O caminho principal mostra uma consulta comum; os blocos laterais mostram o que acontece no servidor e como a aplicação lida com segurança e falhas.

● Front-end / cliente● API / comunicação● Back-end / lógica● Banco de dados● Resposta

Fluxo completo de uma aplicação web

Exemplo: entrar na conta ou carregar uma lista de dados.

🧑

1. Usuário interage

Clica em “Entrar”, pesquisa algo ou envia um formulário.

Evento
clique / submit
🎨

2. Front-end (navegador)

HTML estrutura, CSS estiliza e JavaScript valida campos e prepara os dados.

Cliente
fetch() + HTTPS
🔌

3. Requisição HTTP para a API

Envia método (GET/POST…), URL, cabeçalhos e, quando necessário, corpo JSON.

Request
internet / roteamento
🛡️

4. Servidor recebe e verifica

Roteamento, autenticação, autorização, validação dos dados e limites de uso.

Back-end
requisição válida?
✅

Sim: executar regra

Controlador/serviço aplica as regras do negócio.

⛔

Não: tratar erro

Responder com status adequado, como 400, 401 ou 403.

consulta / atualização
🗄️

5. Banco de dados (quando necessário)

O back-end consulta, cria ou atualiza registros usando uma consulta segura.

Persistência
resultado dos dados
⚙️

6. Back-end monta a resposta

Aplica regras finais e transforma o resultado em JSON ou outro formato.

Response
HTTPS + status HTTP
📦

7. API devolve a resposta

Ex.: 200 OK, 201 Created, 400 Bad Request ou 500 Internal Server Error.

JSON
then / await + tratar estado
✨

8. Front-end atualiza a interface

Mostra os dados, confirma a ação ou exibe uma mensagem de erro.

UI
🔁
O ciclo continua. Cada nova interação pode iniciar outra requisição. Cache, filas e serviços externos podem entrar no fluxo quando a arquitetura precisa deles.

Nota: nem toda requisição consulta o banco; algumas usam cache, arquivos ou serviços externos. Senhas e segredos não devem ficar no código do navegador.

03 / dois lados, um produto

Front-end × Back-end.

Um lado cuida da experiência; o outro garante que a lógica e os dados funcionem com segurança.

🪄

Front-end

A parte com que a pessoa interage diretamente.

  • ✓
    Interface e experiênciaLayout, navegação, acessibilidade e responsividade.
  • ✓
    Estado e eventosCliques, formulários, carregamento e mensagens.
  • ✓
    Comunicação com APIsEnvia pedidos e interpreta respostas; não guarda segredos.
  • ✓
    Ferramentas típicasHTML, CSS, JavaScript/TypeScript e React/Vue.
🧠

Back-end

A parte que processa regras e protege os recursos.

  • ✓
    Regras de negócioCalcula valores, verifica permissões e coordena operações.
  • ✓
    Autenticação e autorizaçãoConfirma identidade e decide o que cada pessoa pode fazer.
  • ✓
    Dados e integraçõesConsulta banco, serviços externos e filas quando necessário.
  • ✓
    Ferramentas típicasNode.js, Python, Java, SQL, logs e testes de servidor.

06 / decodificador de dev

Glossário sem mistério.

Os termos que aparecem quando as caixas do fluxograma começam a conversar.

HTTP

Protocolo de comunicação.
Define como cliente e servidor enviam pedidos e respostas.

API

Contrato de comunicação.
Expõe operações que outros programas podem chamar.

JSON

Formato de dados.
Representa informações em pares de chave e valor.

CRUD

Operações básicas.
Criar, ler, atualizar e excluir registros.

SQL

Linguagem de consulta.
Usada para trabalhar com dados em bancos relacionais.

Deploy

Publicação.
Levar uma versão do software para um ambiente de execução.

Auth

Identidade e permissão.
Autenticação identifica; autorização define o que pode ser acessado.

CORS

Regra do navegador.
Controla quando uma página pode ler respostas de outra origem.
